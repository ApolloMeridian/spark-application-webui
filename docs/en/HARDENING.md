# Hardening changes (1.5.3)

Version 1.5.3 includes the security and performance changes below. Back up PostgreSQL and validate the upgrade before rollout.

## Upgrade requirements

- Set `backend.publicURL` to the browser-visible origin, without a path. Helm can derive it from the explicit OIDC callback or Ingress host/TLS. An external TLS terminator not represented in the chart requires an explicit value. Client Forwarded headers no longer determine trust or Secure cookies.
- OIDC requires an explicit absolute `oidc.redirectURL`, exactly matching the provider registration. Dynamic request-header callbacks are not supported.
- Mutation clients without Origin/Referer must send JSON or `X-Requested-With: SparkControlCenter`; binary parts use the latter. Explicit foreign or `null` origins are denied even with these headers.
- Upgrade RBAC: the backend needs `get` on Services to validate Driver UI ownership. ExternalName, unrelated Services and selectors not selecting the actual Driver are rejected.
- Spark UI uses PostgreSQL-backed read-only tickets scoped to one application and parent session (15-minute maximum). Logout, disabling/moving the user or namespace revocation invalidates access. The parent refreshes the frame every ten minutes, preserving its reported view. Ticket paths are redacted in backend/Nginx logs and use no-referrer. Do not share UI ticket URLs.
- Existing templates/rules migrate to their recorded creator's **current** tenant, or the inaccessible `_legacy_unassigned` marker if the creator is missing. Alerts inherit their rule's tenant; alerts without an identifiable rule are quarantined too. Historical tenant moves cannot be reconstructed. Review assignments before opening access; assign quarantined records to a verified tenant in PostgreSQL. Versions inherit their parent template tenant. Avoid mixed old/new backend replicas during this security upgrade.
- History ownership is immutable per application UID, not inferred from the latest job using the same name. Legacy rows with unknown ownership remain `tenant_id IS NULL` and are hidden from scoped reads until re-observed or verified by an operator. No history is deleted. Review `SELECT application_id,namespace,application_name FROM spark_application_history WHERE tenant_id IS NULL;` after migration; assign a verified tenant ID, or `''` only for confirmed namespace-shared external jobs. Never blanket-mark unknown workflow history as shared.
- Storage containers need writable `/tmp`. The chart supplies disk-backed `emptyDir` (256 MiB) with GID 65532. Standalone read-only containers need an equivalent mount. Parts are mode-0600 temporary files, normally removed after each request; Pod replacement clears the volume. Budget node ephemeral storage, not just RAM.
- Go image builds require BuildKit (`DOCKER_BUILDKIT=1`) and reuse module/compiler caches outside the runtime image. Rollback requires stopping writers and restoring a compatible application/database pair; retain a backup of post-upgrade data before restoring an older backup.

## Security boundaries implemented

- Both Go components require Go 1.26.10; Docker builds use the matching supported patch release. Frontend minimums include DOMPurify 3.4.17, Vite 6.4.4 and Vitest 5.0.3. CI rejects high/critical npm findings. Dependency checks are snapshots of the advisory databases, not a guarantee against future disclosures.
- Live Pod correlation uses owner UID, exact application labels or the exact `spark-app-selector` obtained from a validated Driver; the only name fallback is an exact unlabeled Driver name. Conflicting ownership wins; job-name prefixes never select another job's Executors. Kill also selects a validated Driver, never an arbitrary status field; if none can be verified it returns 409 without terminating Pods or changing restart policy.
- Spark UI is untrusted workload content. The iframe and response CSP both remove same-origin privileges; direct proxy navigation is sandboxed too. Console Cookie/Authorization are stripped before contacting Driver; upstream cookies/CSP/CORS cannot relax isolation. Prefix rewriting uses validated configuration. Only the GET-only proxy permits `Origin: null` AJAX authenticated by its scoped path ticket, without requiring the console cookie; console APIs do not permit null-origin reads or mutations.
- Templates/rules/alerts have scoped SQL and tenant columns. Summaries, history and fingerprints exclude other tenants' successful workflow resource bindings. Failed/unsubmitted task rows cannot claim a resource name. External non-workflow jobs remain shared within authorized namespaces: use separate Kubernetes namespaces for strict workload isolation and prefer workflow name suffixes.
- Authentication account/source attempt windows are coordinated in PostgreSQL; per-process hashing is bounded to four concurrent calls. Quota database failure rejects new attempts rather than bypassing the budget.
- Alert evaluation retains its PostgreSQL lease and per-job failure isolation. Webhooks retain redirect/DNS/metadata protection and now use the persistent delivery queue described below.
- `networkPolicy.enabled` protects backend and frontend. Backend ingress defaults to this release's frontend; add scrapers/trusted callers explicitly. Backend egress is unrestricted until `backend.networkPolicy.egress` is set. Storage examples restrict **ports**, not destination addresses. Customize CNI destination rules; do not accidentally block metadata required by GKE KSA WIF.

## Persistent coordination and collection

- Scheduler planning persists submit/kill intents in PostgreSQL. Kubernetes observations, dry-run, create and termination run outside transactions. Claims expire after 90 seconds, RPCs are bounded to 20 seconds, and random lease tokens fence acknowledgements. Retry identity includes the task attempt. Recovery recognizes an already-created application; current permissions/cancellation are checked again, with durable compensation for an accepted create. This is not an atomic transaction with Kubernetes: bounded in-flight side effects remain possible.
- Webhooks use a transactional outbox with immutable payloads and stable `X-Spark-Delivery-ID`/`Idempotency-Key`. At most four active delivery leases across replicas; transport failures retry with exponential backoff capped at 15 minutes. Acknowledgement loss can duplicate delivery: receivers must deduplicate. Completed rows retain seven days/up to 100000 records; 10000 pending records cause explicit backpressure rather than silent loss. Endpoint changes do not redirect old records to a new receiver.
- Storage replicas sharing one schema now share transfer/request concurrency and per-user/tenant minute windows. Leases expire after 15 seconds and renew every five seconds; renewal loss cancels streaming/provider requests. Rolling configurations use the strictest live budget. Multipart session locks also use durable leases, not pinned database connections. SDK/network cancellation is cooperative; leases cannot make provider writes transactional.
- Login account/source minute budgets are shared in PostgreSQL; bcrypt concurrency remains bounded per process. Source is the observed socket peer, not client-controlled forwarded headers. A proxy may aggregate sources, so ingress per-client controls remain useful.
- One namespace LIST/WATCH reflector per backend shares complete paged snapshots, starts watching from the listed resourceVersion, and invalidates on disconnect/410. This is a purpose-built reflector, not client-go SharedInformer. Authoritative lifecycle operations still read Kubernetes directly.
- The jobs page uses SQL filtering, tenant checks, sorting, favorites, count and LIMIT/OFFSET over a live index. A DB-clock namespace lease coordinates collection across replicas every five seconds; fencing prevents an expired collector from overwriting a replacement. Missing or older-than-90-second collections return 503/retry. Queries use one repeatable-read snapshot. This bounded freshness is for display, never authorization to mutate.
- Historical tenant quarantine and one-time Bootstrap revocation semantics from the first round remain in force. Destination-level CNI egress and real-cloud IAM/Kubernetes acceptance remain deployment responsibilities.

## Validation and references

Run `npm audit`, `npm test`, `npm run build`, `npm run docs:check`, `node scripts/security-browser-test.mjs`, `node scripts/object-storage-local-test.mjs` and `node scripts/object-storage-helm-test.mjs`. The security browser fixture exercises the production sandbox policy in Edge/Chromium; HTTP and SQL tests cover ticket authorization/revocation. Docker integration uses isolated PostgreSQL/MinIO. Tests cover shared-namespace tenant reads/writes/versions, failed name collisions, scheduler/config lock separation, alert lease competition/recovery, proxy ownership, CSRF and credential stripping. GCS SDK/protocol fixtures do not replace real WIF/IAM acceptance.

See the source-checked [API/environment/table reference](REFERENCE.md). Keep private audit reports, values, credentials and local artifacts out of Git.

CI also runs `go run golang.org/x/vuln/cmd/govulncheck@v1.9.0 ./...` separately in `backend` and `object-storage`. The gate checks reachable symbols; inspect verbose package/module findings too. The unused, unmaintained `x/crypto/openpgp` package remains a module-level advisory because the supported bcrypt dependency shares its module; OpenPGP is not imported. No production penetration test or full operating-system image CVE scan is claimed.
